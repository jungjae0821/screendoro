# 최초 환경 구성 (design-setup)

screendoro 2단계에서 읽는 절차다. 프로젝트의 디자인 방향을 정하고, `DESIGN.md`와 토큰, 기본 구조를 만든다. 프로젝트당 한 번만 한다.

우선순위는 `SKILL.md`와 같다: 사용자 지시 > `house-rules.md` > 이 문서. 0-1단계의 확정 구조와 1단계 랜딩 전략 결과물이 있으면 그것을 먼저 따른다.

## 순서

1. 프로젝트 파악 (1절)
2. 화면 성격 정하기 (2절)
3. 방향 후보 만들기 (3절)
4. 시안 선택: `SKILL.md` 2-1을 그대로 수행한다. 이 문서의 3절 후보가 "자체 방향" 시안의 재료다.
5. `DESIGN.md` 작성 (5절)
6. 토큰 옮기기와 기본 구조 (6절)

3절을 시작하기 전에 `slop-tells.md`를 읽는다. 시안을 그리기 전과 화면을 만들 때 모두 4절 품질 기준을 지킨다.

---

## 1. 프로젝트 파악

새로 묻기 전에 이미 있는 것부터 읽는다.

- 0-1단계 초안 기록(`.claude/screendoro-draft.md`), 1단계 랜딩 전략 결과물
- `package.json`, 프레임워크, CSS 방식(Tailwind, CSS Modules, 순수 CSS 등)
- 로고, 브랜드 색, 이미지, 폰트 파일 같은 기존 자산
- 사용자가 준 레퍼런스

그다음 아래 네 가지를 한 줄씩 정리해 사용자에게 보여준다. 모르는 것은 지어내지 말고 한 번에 모아서 묻는다.

- **무엇인가**: 이 제품이 다른 것과 다른 점 한 문장
- **누가, 어디서 쓰나**: 대상 사용자와 실제 사용 장면 (사무실 모니터, 출퇴근 중 휴대폰, 밤에 침대에서 등)
- **첫 화면이 증명할 것**: 방문자가 첫 화면에서 알아야 하는 한 가지
- **피할 것**: 사용자가 싫다고 한 것, 경쟁사와 겹치면 안 되는 것

## 2. 화면 성격 정하기

대표 화면의 성격을 하나 고른다. 제품이 아니라 **그 화면**을 기준으로 고른다. 같은 제품이어도 소개 페이지는 설득형이고 관리 화면은 작업형이다.

| 성격 | 방문자의 성공 | 예 | 디자인의 무게 |
|---|---|---|---|
| **설득형** | 이해하고 행동한다 | 랜딩, 마케팅, 가격 | 개성과 인상. 과감한 방향을 쓴다 |
| **작업형** | 할 일을 끝낸다 | 대시보드, 앱, 설정, 관리 도구 | 훑어보기 쉬움, 일관성, 익숙한 패턴. 개성은 세부에서 낸다 |
| **읽기형** | 내용을 이해한다 | 문서, 글, 도움말 | 읽기 편한 구조, 글줄 길이, 위계 |
| **감상형** | 작품을 본다 | 포트폴리오, 갤러리 | 작품이 먼저 보이고 화면 틀은 물러선다 |

마커에 `"surfaceMode"`로 적는다 (`persuade` / `operate` / `read` / `experience`).

## 3. 방향 후보 만들기

"자체 방향" 시안의 재료를 만드는 절차다. 레퍼런스 기반 시안은 `design-reference.md`를 따르고, 이 절은 그 경우에도 자체 방향을 고를 때 쓴다.

### 3-1. 뻔한 길부터 적는다

이 업종에서 늘 나오는 화면(예: SaaS면 어두운 배경 + 보라 그라디언트 + 카드 3개)과, 그 반대로 뒤집기만 한 화면을 한 줄씩 적는다. 둘 다 **뻔한 길**이다. 후보 목록에 넣지 않는다.

제품 이름이나 비유를 글자 그대로 그림으로 옮긴 방향(예: "숲"이라는 이름 → 초록 숲 사진)도 뻔한 길로 보고, 후보 중 많아야 하나만 쓴다.

`slop-tells.md` 1절의 다섯 유형(크림 + 세리프 + 테라코타, 검정 + 형광 강조, 신문 지면형, SaaS 카드 세트, 템플릿 장식)도 뻔한 길이다. 업종과 상관없이 나오는 기본값이라 후보에 넣지 않는다. 후보가 한 축이라도 이 유형과 겹치면(예: 바탕이 크림) 그 축을 제품 주제 쪽으로 옮긴다. 사용자가 이 중 하나를 직접 원하면 그때만 쓴다.

### 3-2. 사용자의 세계에서 후보를 뽑는다

대상 사용자가 잘 아는 **실물, 인쇄물, 장소, 관습, 화면 전통**에서 시각 체계 6~7개를 뽑는다. 재료 계열의 예: 공공 표지(지하철 노선도, 경기장 좌석 안내), 포장과 라벨(약 봉투, 세탁 라벨), 장소(시장 좌판 가격표, 수영장 레인), 기록 관습(바둑 기보, 악보), 인쇄물(기차 시간표).

- 위 예는 재료 계열이 이렇게 넓을 수 있다는 것을 보여 줄 뿐이다. 그대로 후보로 쓰지 말고, 이 제품의 대상 사용자 세계에서 새로 뽑는다.
- 신문 지면, 잡지 편집, 요리책처럼 **편집 디자인**을 흉내 낸 후보는 `slop-tells.md` 1절 3번 유형과 겹치므로 쓰지 않는다.

- 후보마다 두 줄을 적는다. ① 왜 이 사용자에게 와닿고 제품의 핵심을 담을 수 있는지 ② 어떻게 생겼는지 (바탕색과 주색, 글자 대비, 한눈에 알아보게 하는 특징 하나)
- 비슷한 후보는 하나로 친다. 후보 절반 이상이 같은 재료(모두 종이 인쇄물, 모두 화면 UI 등)면 덜 판 것이다. 재료 계열이 3개 이상 되게 한다.
- **작업형·읽기형 화면**에서는 사용자가 다루는 도구 자체(터미널, 계기판, 조종 패널)를 후보로 쓰지 않는다. 도구 흉내는 분장처럼 보인다.
- **설득형·감상형 화면**에서는 도구 흉내를 많아야 하나만 쓴다.

### 3-3. 완성된 방향으로 만든다

후보를 시안 수만큼 골라 **방향**으로 완성한다. 방향 하나는 아래를 모두 갖춘다.

- **세계**: 어떤 시각 체계를 가져왔는지 한 줄
- **첫 화면**: 첫 화면에서 무엇이 어떻게 보이는지
- **색**: 바탕, 글자, 주색, 보조색. 라이트·다크는 업종이 아니라 1절의 사용 장면으로 고른다.
- **글자 대비**: 폰트는 모든 시안이 경기천년체로 같으므로 크기 단계, 굵기, 자간, 행간으로 성격을 낸다.
- **배치**: 그리드, 정렬, 비율, 여백의 리듬
- **질감과 깊이**: 그림자, 선, 면, 이미지 처리 방식
- **위험**: 이 방향이 실패할 수 있는 점 한 줄 (비교 페이지 설명에 쓴다)

방향끼리는 세계, 배치, 색, 분위기가 모두 달라야 한다. 색만 바꾼 것은 같은 방향이다.

### 3-4. 정석안

사용자가 "무난하게", "업계 표준처럼"을 원하면 정석안을 따로 만든다. 이때는 사용자에게 옆에 둘 만한 제품 2~3개를 묻고, 그 제품들의 완성도를 기준으로 삼는다. 비꼬거나 몰래 개성을 섞지 않고 정석을 제대로 만든다. AI가 먼저 정석안을 권하지 않는다.

### 3-5. 사실과 예시 데이터

- 가격, 고객사, 수치, 없는 기능 같은 사실 주장은 지어내지 않는다.
- 방향을 보여주는 데 필요한 예시 데이터(그래프, 목록, 샘플 글)는 만들어 써도 된다. 실제로 착각할 수 있는 곳에는 예시라고 표시하고, 나중에 실제 자료로 바꿀 목록을 완료 보고에 남긴다.
- 예시 데이터가 아직 없다는 이유로 과감한 방향을 포기하지 않는다.

## 4. 품질 기준

시안과 화면 모두에 적용한다. 고정 규칙(`house-rules.md`)이 이 절보다 우선한다. 4단계 antislop 점검과 겹치는 항목은 거기서 다시 확인한다.

### 4-1. 확인할 것

- **대비**: 본문과 입력창 안내 글자 4.5:1 이상, 큰 글자 3:1 이상. 색 있는 면 위의 보조 글자는 회색 대신 그 면의 색이나 글자색을 옅게 섞어 만든다.
- **간격**: 묶음 안은 촘촘하게, 묶음 사이는 넉넉하게. 제목 위 여백이 제목 아래 여백보다 크다.
- **글자**: 한글 본문 한 줄은 대략 35~45자, 라틴 본문은 65~75자. 제목은 `text-wrap: balance`, 한국어 본문은 `word-break: keep-all`. 크기와 굵기 단계가 눈에 띄게 구분된다. 실제 문구를 넣고 모든 폭에서 넘치는 곳을 고친다.
- **깊이**: 그림자는 위치 이동과 부드러운 번짐을 함께 쓴다. 이동 없이 색만 번지는 후광은 장식이다.
- **모션**: 화면에 의도한 순간 하나. 모든 섹션에 같은 등장 효과를 붙이지 않는다. 처음부터 보이는 상태에서 시작하고, 끝이 부드럽게 느려지는 곡선을 쓴다.
- **상태**: 마우스 올림, 비활성, 불러오는 중, 오류, 빈 화면, 키보드 포커스
- **브라우저 기본 요소**: 글자 선택 색, 입력 커서, 포커스 링, 스크롤바, 표 숫자(`font-variant-numeric: tabular-nums`)도 팔레트에 맞춘다.
- **문구**: 제품의 말로 쓴다. 버튼은 하는 일을 말하고, 오류는 문제와 해결 방법을 말한다.

### 4-2. 이유 없이 쓰지 않는 것

아래는 AI 화면에서 흔한 기본값이다. 사용자의 요청이나 `DESIGN.md`에 이유가 적힌 선택이면 쓸 수 있다. 이유 없이 손이 갔다면 그 요소를 다시 설계한다. 전체 목록은 `slop-tells.md`에 있고, 시안과 화면을 만들기 전에 그 문서를 읽는다.

- 같은 크기 카드(아이콘 + 제목 + 설명)를 반복해 페이지 뼈대로 쓰기. 카드 안에 카드 넣기
- 큰 숫자 + 작은 라벨 + 보조 수치로 된 히어로
- 제목 위 작은 라벨(eyebrow)
- 순서 정보가 없는데 붙인 01 / 02 / 03 번호
- 그라디언트 글씨, 장식용 유리·블러 효과
- 카드나 알림 왼쪽·오른쪽에 붙인 굵은 색 테두리
- 네오브루탈리즘 방향이 아닌데 번짐 없는 딱딱한 그림자
- "기술적인 느낌"을 내려고 쓴 고정폭 폰트
- 이모지나 유니코드 기호로 대신한 아이콘. 아이콘은 한 라이브러리에서 같은 굵기로 쓴다.
- 업종 관습만 보고 고른 라이트·다크

## 5. `DESIGN.md` 작성

고른 시안(2-1)의 값을 프로젝트 루트 `DESIGN.md`에 기록한다. 사용자가 시안을 고르기 전에는 쓰지 않는다.

### 5-1. 머리말: 토큰

YAML 머리말에 실제로 쓰는 값만 적는다. 아래 값은 **형식을 보여 주는 예시**다. 색, 크기, 간격을 그대로 가져다 쓰지 않고 고른 시안의 값을 적는다.

```yaml
---
name: <프로젝트 이름>
description: <한 줄 소개>
surfaceMode: persuade
colors:
  bg: "#eef2ee"
  text: "#17221d"
  primary: "#24624c"
  primary-deep: "#184634"
typography:
  display:
    fontFamily: "'경기천년제목', 'Pretendard', system-ui, sans-serif"
    fontSize: "3.5rem"
    fontWeight: 700
    lineHeight: 1.15
    letterSpacing: "-0.02em"
  body:
    fontFamily: "'경기천년바탕', 'Pretendard', system-ui, sans-serif"
    fontSize: "1.0625rem"
    fontWeight: 400
    lineHeight: 1.75
rounded:
  sm: "6px"
  button: "10px"
spacing:
  xs: "4px"
  sm: "8px"
  md: "16px"
  lg: "32px"
  xl: "64px"
components:
  button-primary:
    backgroundColor: "{colors.primary}"
    textColor: "{colors.bg}"
    rounded: "{rounded.button}"
    padding: "14px 28px"
  button-primary-hover:
    backgroundColor: "{colors.primary-deep}"
---
```

- 다른 토큰은 `{colors.primary}`처럼 참조한다. 컴포넌트는 기본 토큰을 참조할 수 있고, 기본 토큰끼리는 참조하지 않는다.
- 이름은 프로젝트가 이미 쓰는 이름을 따른다. 없으면 뜻이 보이는 이름을 쓴다.
- 고정 규칙: 폰트는 경기천년체, 버튼 반경은 8px 이상.

### 5-2. 본문: 여덟 절

아래 순서로 쓴다. 해당 없는 절은 빼고, 지어낸 규칙으로 채우지 않는다.

1. **개요**: 고른 방향, 세계, 화면 성격, 한 줄 원칙
2. **색**: 역할별 색과 쓰는 곳
3. **타이포그래피**: 크기 단계와 위계, 줄바꿈 규칙
4. **레이아웃**: 그리드, 최대 폭, 반응형 규칙
5. **깊이**: 그림자, 겹침, 면 구분 방식
6. **모양**: 모서리 반경, 선, 형태 언어
7. **컴포넌트**: 버튼, 입력창, 내비게이션, 카드, 이 프로젝트만의 대표 컴포넌트
8. **할 것 / 하지 않을 것**: 고정 규칙과 이 방향에서 지킬 것

**값마다 이유를 한 줄씩 붙인다** (예: "본문 행간 1.75: 경기천년바탕은 획이 가늘어 줄 사이가 넓어야 읽힌다"). 이유가 적힌 값은 4단계에서 목적 있는 선택으로 본다. 레퍼런스에서 온 값은 근거 번호를 함께 적는다.

## 6. 토큰 옮기기와 기본 구조

- `DESIGN.md`가 원본이다. 코드의 토큰은 여기서 옮긴다.
  - 순수 CSS: `:root`에 CSS 변수로 (`--color-primary` 등)
  - Tailwind: 설정 파일이나 `@theme`에 같은 이름으로
  - Astryx 프로젝트: `astryx.md` 2~3절을 따른다.
- 기본 구조로 아래를 만든다.
  - 경기천년체 `@font-face` (파일 출처는 `house-rules.md` 1절. 주소를 지어내지 않는다)
  - 기본 리셋, 본문 글자·행간·색, `word-break: keep-all`
  - 4-1의 브라우저 기본 요소 (선택 색, 포커스 링, 스크롤바)
  - 레이아웃 기본값 (최대 폭, 바깥 여백)
- 화면 컴포넌트는 여기서 만들지 않는다. 3단계에서 만든다.

## 하지 않는 것

- 사용자가 시안을 고르기 전에 `DESIGN.md`나 토큰을 확정하지 않는다.
- 뻔한 길을 후보에 몰래 넣거나, AI가 먼저 정석안을 권하지 않는다.
- 레퍼런스나 유명 서비스의 화면을 구조째 베끼지 않는다. 패턴과 원리만 가져온다.
- 지어낸 사실 주장, 지어낸 폰트·이미지 주소를 쓰지 않는다.
- 마커가 있는 프로젝트에서 이 절차를 다시 하지 않는다. 사용자가 리디자인을 요청하면 그때만 다시 한다.
