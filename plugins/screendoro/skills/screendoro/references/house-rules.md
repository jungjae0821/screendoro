# 고정 규칙 (house-rules)

screendoro 사용자가 **모든 프로젝트**에 적용하는 화면 규칙이다. 2·3단계에서 화면에 반영하고, 4단계에서 위반을 찾아 고친다.

우선순위: 사용자 지시 > **이 문서** > 프로젝트 `DESIGN.md` > 다른 `references/` 문서 > `frontend-design` 기본값 > Astryx 기본값.
`DESIGN.md`나 `landing-visual-preset.md`가 이 문서와 다르면 이 문서를 따른다. `DESIGN.md`에 이유가 적혀 있어도 마찬가지다.
Astryx 같은 컴포넌트 라이브러리를 쓰는 프로젝트에서도 똑같이 적용한다. 라이브러리의 기본 모양이 이 문서와 다르면 테마나 덮어쓰기로 이 문서에 맞춘다 (`astryx.md` 3·6절).

---

## 1. 폰트: 경기천년체

- 화면의 모든 글자는 경기천년체로 쓴다.
  - 제목, 버튼, 내비게이션, 강조 문구: **경기천년제목** (Light / Medium / Bold)
  - 본문, 설명문, 표, 폼 입력값: **경기천년바탕** (Regular / Bold)
- 숫자·코드처럼 고정폭이 기능상 꼭 필요한 곳만 예외로 고정폭 폰트를 쓸 수 있다.
- 폴백: `'경기천년제목'`(또는 `'경기천년바탕'`) 다음에 `'Pretendard', system-ui, sans-serif`를 둔다.
- 폰트 파일:
  - 프로젝트에 이미 폰트 파일이나 확인된 웹폰트 주소가 있으면 그것을 쓴다.
  - 없으면 사용자에게 파일을 받는다. 웹폰트 CDN 주소를 지어내지 않는다.
  - 파일을 구하지 못했으면 `font-family` 선언과 폴백만 넣고, 완료 보고에 "경기천년체 파일 미적용"이라고 적는다.
- 한국어 본문에는 `word-break: keep-all`을 함께 쓴다.

## 2. 버튼: 둥근 모서리

- 모든 버튼(`button`, 버튼 모양 링크, `input[type=submit]` 등)은 모서리가 둥글어야 한다. 각진 버튼(반경 0~7px)은 쓰지 않는다.
- 반경은 **8px 이상**. `DESIGN.md`에 버튼 반경 값이 있고 8px 이상이면 그 값을 쓴다.
- 정해진 값이 없으면 높이의 절반(알약형)을 기본으로 쓰지 않는다. 디자인 방향에 맞는 8px 이상의 값 하나를 정하고 `DESIGN.md`에 이유와 함께 적는다. 알약형은 방향이 요구할 때만 쓴다 (모든 요소가 알약 모양인 화면은 대표적인 AI 기본값이다).
- 한 화면 안의 버튼은 같은 반경 규칙을 따른다. 버튼마다 반경이 제각각이면 안 된다.
- 이 규칙은 **버튼**에만 해당한다. 입력창, 카드, 배지, 모달의 반경을 버튼과 같게 맞추지 않는다. 반경은 요소의 종류와 위계를 나누는 도구로 쓴다 (예: 버튼 10px, 입력창 6px, 큰 면 0~4px).

## 3. 이중 테두리 금지

선이 두 겹으로 보이는 처리는 모두 금지다.

- `border-style: double`
- 테두리가 있는 요소에 `outline`이나 테두리 역할의 `box-shadow`(블러 0, 퍼짐 1px 이상인 그림자)를 겹친 것
- 테두리가 있는 요소 안에 테두리가 있는 요소를 바짝 붙여 넣은 것 (카드 안 카드, 테두리 상자 안 테두리 입력창 등). 안쪽과 바깥 테두리 사이 간격이 16px 미만이면 이중 테두리로 본다.
- 테두리 + 안쪽 그림자(`inset`)로 선을 하나 더 만든 것
- 테두리 바로 바깥이나 안쪽에 선 역할을 하는 가상 요소(`::before`, `::after`)를 덧댄 것

고치는 법: 둘 중 하나만 남긴다. 기본은 **안쪽 테두리를 지우고** 간격이나 면 색으로 구분한다.

대신 이렇게:
- 카드 안 카드 → 안쪽은 테두리 없이 면 색 한 단계(바탕보다 살짝 진하거나 옅게)로 구분하거나, 바깥 카드를 없애고 여백으로 묶는다.
- 테두리 상자 안 입력창 → 상자 테두리를 지우고 입력창 테두리만 남긴다. 입력창 테두리는 "여기에 쓴다"는 기능이라 남기는 쪽이다.
- 테두리 + 그림자 → 위계가 높은 면(모달, 떠 있는 메뉴)은 그림자만, 바닥에 붙은 면은 테두리나 면 색만.

예외: 키보드 포커스 링(`:focus-visible`)은 접근성 요구사항이라 지우지 않는다. 대신 포커스 링이 다른 선과 겹쳐 세 겹이 되지 않게 `outline-offset`을 준다.

## 4. 불필요한 밑줄과 요소 금지

목적 없는 장식은 넣지 않는다. 아래는 넣지 않고, 있으면 지운다.

**밑줄**
- 제목, 섹션 제목 아래 장식 밑줄이나 짧은 강조 막대
- 내비게이션, 버튼, 카드 제목 링크의 밑줄
- 강조하려고 단어 아래 긋는 형광펜·물결 밑줄
- 제목 아래, 섹션 사이의 구분선 중 레이아웃상 필요 없는 것

예외: **본문 문장 속 링크**는 색만으로 구분하면 접근성 위반이다. 밑줄을 남기거나 굵기 같은 색 이외의 표시를 둔다.

**요소**
- 제목 위 작은 라벨(eyebrow), 의미 없는 배지·태그
- 내용과 상관없는 장식 아이콘, 모든 제목 앞에 붙인 아이콘
- 배경의 흐릿한 원형 블롭, 장식용 점·격자 패턴, 의미 없는 그라디언트 면
- 내용이 같은 말을 반복하는 보조 문구, 기능 없는 빈 카드나 자리표시자
- 클릭되지 않는 화살표, 동작하지 않는 "더 보기" 같은 장식성 컨트롤

판단 기준: "이걸 지우면 사용자가 정보나 기능을 잃는가?" 잃지 않으면 불필요한 요소다.

### 4-1. 대신 이렇게

지우기만 하면 위계가 사라져 밋밋한 기본 화면이 된다. 장식이 하던 일(눈길 끌기, 구분, 분류)은 아래 처리로 옮긴다. 어떤 처리를 쓸지는 `DESIGN.md`의 방향에서 고른다.

| 지운 것 | 그 장식이 하던 일 | 대신 쓰는 처리 |
|---|---|---|
| 제목 아래 장식 밑줄, 강조 막대 | 제목을 눈에 띄게 | 제목과 본문의 크기·굵기 대비를 키운다. 제목 위 여백을 아래 여백보다 넉넉하게 둔다 |
| 섹션 사이 구분선 | 섹션 나누기 | 섹션 사이 여백을 묶음 안 여백보다 확실히 크게. 섹션마다 면 색을 한 단계 바꾸거나 정렬·폭을 바꿔 리듬을 낸다 |
| 형광펜·물결 밑줄 | 단어 강조 | 문장 자체를 짧고 구체적으로 고친다. 꼭 필요하면 굵기 하나만 바꾼다 (한 단어만 다른 색으로 칠하는 것도 AI 기본값이다) |
| 제목 위 eyebrow 라벨 | 분류 알려 주기 | 제목에 분류가 드러나게 쓴다. 분류가 내비게이션 정보면 상단 내비나 현재 위치 표시로 옮긴다 |
| 모든 제목 앞 아이콘, 장식 아이콘 | 시선 잡기, 훑어보기 | 글자 위계(크기, 굵기, 들여쓰기)로 훑어보게 만든다. 아이콘은 뜻이 있는 곳(동작, 상태, 파일 종류)에만 |
| 배경 블롭, 점·격자 패턴, 그라디언트 면 | 빈 공간 채우기, 분위기 | 실제 콘텐츠(제품 화면, 사진, 실제 데이터)를 크게 쓴다. 없으면 면 분할(색 면 하나, 비대칭 배치)과 큰 글자로 화면을 짠다 |
| 의미 없는 배지·태그 | 새로움, 특별함 표시 | 실제 상태(재고 없음, 마감 임박 등)만 배지로. 나머지는 문장으로 |
| 같은 말 반복하는 보조 문구 | 빈칸 채우기 | 지운다. 남은 여백은 그대로 둔다. 여백도 위계다 |
| 기능 없는 빈 카드, 자리표시자 | 그리드 맞추기 | 그리드 칸 수를 내용에 맞게 줄이거나 배치를 바꾼다 |
| 장식 화살표, 동작 없는 "더 보기" | 다음 행동 암시 | 실제로 동작하게 만들거나 지운다. 버튼 글자가 하는 일을 말하면 화살표가 필요 없다 |

지운 뒤 화면이 비어 보이면 장식을 되돌리지 말고, 이 화면의 시그니처 요소(`SKILL.md` 3-1)가 충분히 큰지부터 본다.

## 5. 4단계 점검 절차

antislop 점검과 같은 시점에 한다. 이 문서의 위반은 모두 **필수** 항목이다.

1. **코드 검색**: 만든 화면의 스타일과 마크업에서 아래를 찾는다.
   - `double`, `outline:`, `box-shadow`(블러 0 퍼짐 있는 것), `inset`
   - `underline`, `text-decoration`, `border-bottom`, `::after`, `::before`
   - 버튼 스타일의 `border-radius`(또는 `rounded-none`, `rounded-sm`, `rounded`)
   - `font-family`(경기천년체가 아닌 폰트)
2. **렌더링 검사**: `render-check.md` 순서로 화면을 띄운 뒤, 폭마다 `references/house-check.js` 내용을 `javascript_tool`에 그대로 넣어 실행한다. 읽기만 하고 페이지를 바꾸지 않는다. 결과의 각 목록이 비어 있어야 통과다.
3. **눈으로 확인**: 스크립트는 "불필요한 요소"를 다 잡지 못한다. 캡처를 보고 4절 목록에 해당하는 것이 있는지 확인한다.
4. **수정**: 위반은 지우는 쪽으로 고치되, 지운 자리는 3절 "대신 이렇게"와 4-1절 표의 처리로 채운다. 이중 테두리는 한 겹만 남기고, 불필요한 밑줄과 요소는 삭제한다. 폰트와 버튼 반경은 규칙 값으로 바꾼다.
5. **재점검**: screendoro 4단계 재점검(1회)에 포함해 고친 화면만 다시 확인한다.

## 체크리스트

- [ ] 모든 글자가 경기천년제목·경기천년바탕 (예외는 고정폭이 필요한 곳뿐)
- [ ] 경기천년체 파일이 실제로 로드됨 (못 했으면 보고에 "미적용")
- [ ] 모든 버튼 반경 8px 이상, 화면 안에서 같은 규칙
- [ ] 입력창·카드·배지가 버튼 반경을 그대로 따라 하지 않음 (알약형이 방향의 선택이 아니면)
- [ ] 지운 장식 자리가 4-1절 처리로 채워졌음 (지우기만 해서 위계가 사라지지 않음)
- [ ] 이중 테두리 없음 (포커스 링 예외)
- [ ] 장식 밑줄 없음 (본문 속 링크 예외)
- [ ] 불필요한 장식 요소 없음
