# 초안 맞추기 (draft-first)

screendoro 0-1단계에서 읽는 절차다. 화면의 구조는 사용자가 먼저 생각하고, AI는 그 초안에 답한 뒤 서로 다른 부분을 사용자가 판정한다.

목적은 사용자가 생각하는 단계를 지키는 것이다. AI가 먼저 안을 내면 사용자는 그 안을 기준으로 생각하게 된다. 그래서 이 절차에서 AI가 하는 일은 세 가지뿐이다.

- 초안을 받기 전에는 제안하지 않는다.
- 초안을 사용자가 말한 그대로 기록한다.
- 초안과 다르게 한 곳을 숨기지 않는다.

초안의 내용을 대신 만들어 주는 것은 이 절차의 일이 아니다.

## 언제 쓰나

- 새 화면·페이지를 만들거나 화면을 크게 재구성할 때마다, 0단계 판별 직후에 한다. 랜딩 전략(1단계), 시안(2-1), 화면 코드(3단계)보다 먼저다.
- 마커가 있는 프로젝트(2단계를 건너뛰는 작업)에서도 한다.
- 여러 화면을 한 번에 만들면 화면별 초안을 한 번에 모아서 받는다. 초안을 받지 못한 화면은 "초안 없음"으로 기록한다.
- 문구, 색·간격, 버그 수정 같은 작은 변경에는 쓰지 않는다.

## 1. 초안 받기

초안을 받기 전에는 구조, 섹션 구성, 레이아웃, 디자인 방향을 제안하지 않는다. 예시 구조도 들지 않는다.

받는 것은 세 가지다.

1. 화면에 들어갈 요소와 순서
2. 이 화면에서 가장 중요한 것 하나
3. 레퍼런스(URL이나 스크린샷)와 거기서 가져오고 싶은 점

받는 방법:

- 일반 메시지로 묻고 자유 서술로 받는다. AskUserQuestion 선택지로 받지 않는다. 선택지는 AI가 만든 안이라서 초안이 아니다.
- 요청 끝에 "초안 없이 가려면 '초안 없이'라고 하면 된다"를 한 줄로 알린다.
- 사용자가 첫 메시지에 이미 초안을 줬으면 다시 묻지 않고, 세 가지 중 빠진 것만 묻는다.
- 랜딩 작업이면 1단계 사전 질문 중 빠진 것도 이 요청에 함께 묻는다. 묻는 것은 사실과 목적이지 구조가 아니다.
- 형식은 따지지 않는다. 한 줄 목록, 손그림 사진, 말로 푼 설명 모두 초안이다.

초안이 모자랄 때:

- 1번(요소와 순서)이나 2번(가장 중요한 것)이 빠졌으면 빠진 것만 한 번 더 묻는다. 이때도 예시나 후보를 들지 않는다.
- 다시 물어도 정하지 않은 항목은 **빈칸**으로 둔다. AI가 채워서 초안인 것처럼 적지 않는다.
- 사용자가 "초안 없이", "알아서 해줘", "네가 정해줘"라고 하면 건너뛰기로 본다 (5절). "알아서"는 이 문서 어디서든 **AI에게 맡긴다**는 뜻으로 읽는다 (4-4도 같다).

## 2. 초안 기록

`.claude/screendoro-draft.md`에 기록한다. 파일이 이미 있으면 화면 단위로 이어 쓴다.

- "초안" 절에는 사용자의 말을 그대로 옮긴다. 다듬거나, 순서를 바꾸거나, 용어를 고치지 않는다.
- 사용자가 정하지 않은 항목은 "빈칸"에 적는다.
- 손그림이나 스크린샷으로 받았으면 이미지에서 읽은 내용을 적고 "이미지에서 읽음"이라고 표시한다. 읽은 내용이 맞는지 사용자에게 한 번 확인한다.

```markdown
# 초안 기록

## <화면 이름> (YYYY-MM-DD)

### 초안 (사용자 원문)
1. ...
2. ...
- 가장 중요한 것: ...
- 레퍼런스: <URL 또는 "스크린샷 n장"> / 가져오고 싶은 점: ...
- 빈칸: <사용자가 정하지 않은 항목. 없으면 "없음">

### AI 구조안
1. ...

### 차이와 판정
| # | 차이 | 찾은 쪽 | 종류 | AI 이유 | 판정 |
|---|---|---|---|---|---|
| 1 | 후기 섹션을 가격 위로 옮김 | 사용자 | 바꿈 | 레퍼런스가 근거를 먼저 보여줌 | 초안대로 |
| 2 | FAQ 추가 | AI | 채움 | 초안에 없음. 가입 전 질문이 많을 화면 | AI안 |

### 확정 구조
1. ...
```

## 3. 레퍼런스 읽기

사용자가 가져온 레퍼런스는 구조안을 내기 전에 읽는다.

- **URL**: `design-reference.md`의 B·C를 건너뛰고 D(패턴 뽑기)와 E(노트 작성)를 수행한다. 노트는 `.claude/screendoro-refs.md`에 쓴다.
- **스크린샷**: 측정할 수 없으므로 D의 "관찰"만 적고 노트에 "측정 못 함"이라고 쓴다.
- 읽는 초점은 사용자가 "가져오고 싶은 점"으로 꼽은 것과 구조(요소의 순서, 첫 화면 구성, 정보량)다.
- **레퍼런스가 없으면** 한 번 묻는다: 직접 가져올지, 갤러리에서 찾을지(`design-reference.md` A~E), 없이 갈지. 어느 쪽을 골라도 초안은 받는다.
- `design-reference.md`의 "지켜야 할 선"은 그대로 적용한다. 사용자가 가져온 레퍼런스라도 로고, 이미지, 문구, 에셋을 옮기지 않는다.

## 4. AI 구조안과 차이 지적

### 4-1. 구조안 내기

초안과 레퍼런스를 읽고 구조안을 낸다. 구조안은 글로 쓴다: 요소의 순서, 요소마다 담는 내용 한 줄, 가장 강조하는 것. 시안이나 코드는 아직 만들지 않는다.

- 초안과 다르게 할 이유가 없으면 초안대로 한다. 차이를 만들려고 일부러 바꾸지 않는다.
- 초안에 문제가 있다고 판단하면 구조안에서 다르게 하고, 4-3에서 이유를 밝힌다. 문제를 알면서 초안을 그대로 따르지 않는다.
- 초안의 빈칸은 AI가 채운다. 채운 곳은 4-3에서 "채움"으로 공개한다.
- 구조안을 처음 보여줄 때는 차이 표시를 달지 않는다. 구조안만 보여주고 "초안과 다른 부분을 짚어 달라"고 요청한다.

### 4-2. 사용자가 먼저 지적

사용자의 지적을 받는다. 지적마다 `screendoro-draft.md`의 "차이와 판정" 표에 "찾은 쪽: 사용자"로 적는다.

- 사용자가 지적하면서 어떻게 할지도 말했으면 그것이 판정이다.
- AI안에 이유가 있으면 한 줄로 한 번만 말한다. 사용자가 정하면 따르고 다시 주장하지 않는다.

### 4-3. 나머지 차이 공개

사용자의 지적이 끝나면, 사용자가 짚지 않은 차이를 **모두** 공개한다. 사소해 보여도 빼지 않는다. 종류는 세 가지다.

- **바꿈**: 초안의 순서, 내용, 강조를 다르게 한 곳
- **뺌**: 초안에 있는데 구조안에 넣지 않은 것
- **채움**: 초안에 없거나 빈칸이어서 AI가 넣은 것

차이마다 이유를 한 줄씩 붙이고 표에 "찾은 쪽: AI"로 적는다. 남은 차이가 없으면 "나머지 차이 없음"이라고 말한다.

사용자가 지적 없이 "그냥 진행해", "다른 데 없어 보여"라고 해도 이 공개는 생략하지 않는다.

### 4-4. 판정

차이마다 판정을 받는다: **초안대로 / AI안 / 절충**(절충이면 내용을 적는다).

- AI가 공개한 차이의 판정은 AskUserQuestion으로 받아도 된다. 차이가 4개를 넘으면 표로 보여주고 메시지로 받는다.
- 사용자가 "알아서"라고 하면 1절과 같은 뜻(AI에게 맡김)으로 보고 **AI안**으로 한다. 단, 사용자가 이미 판정한 차이는 그대로 둔다. 어느 차이를 AI안으로 정했는지 한 줄 목록으로 알려, 사용자가 되돌릴 수 있게 한다.
- 사용자가 "초안대로 해", "내 것대로"라고 하면 남은 차이를 모두 **초안대로** 한다. 채움은 초안에 없는 내용이므로 넣지 않고, 빈칸을 채운 것만 예외로 AI안을 쓴다.
- 판정을 모두 받으면 "확정 구조"를 적는다. 이후 단계는 초안이 아니라 확정 구조를 따른다.
- 모든 차이의 판정이 끝나기 전에는 랜딩 전략 결과물(1단계), 시안(2-1), 화면 코드(3단계)를 만들지 않는다.

## 5. 건너뛰기

사용자가 명시적으로 건너뛰겠다고 할 때만 건너뛴다. AI가 먼저 건너뛰자고 권하지 않는다.

- 건너뛰면 `screendoro-draft.md`에 `## <화면 이름> (날짜)` 아래 "초안 없음 (사용자가 건너뜀)"만 적고 기존 흐름대로 진행한다.
- 완료 보고의 초안 줄에 "초안 없음"이라고 적는다.
- 건너뛴 것은 그 화면에만 해당한다. 다음 새 화면에서는 다시 초안을 요청한다.

## 6. 이후 단계에서 지키는 법

- **확정 구조는 사용자 지시로 본다.** `DESIGN.md`, `landing-strategy.md`의 섹션 순서, `frontend-design` 기본값보다 우선한다.
- **1단계 랜딩 전략**: 결과물의 섹션 구성은 확정 구조를 따른다. `landing-strategy.md` 6절 순서와 다르면 확정 구조가 이긴다. 6절에는 있는데 확정 구조에 없는 섹션은 넣지 않는다. 필요하다고 판단하면 아래 "나중에 생긴 차이"로 처리한다.
- **2-1 시안**: 모든 시안이 확정 구조(요소와 순서)를 지킨다. 시안끼리는 배치 방식(그리드, 정렬, 비율), 색, 타이포, 분위기로 차이를 낸다.
- **3단계 화면 작성**: 확정 구조대로 구현한다.
- **나중에 생긴 차이**: 판정이 끝난 뒤 어느 단계에서든 확정 구조와 다르게 해야 할 이유가 생기면, 바꾸기 전에 사용자에게 알리고 판정을 받는다. 받은 판정은 표에 이어 적는다.
- **4단계 초안 대조**: 만든 화면을 확정 구조와 항목별로 대조한다. 판정 없이 달라진 곳은 **필수** 항목이다. 확정 구조대로 고치거나, 사용자에게 알리고 판정을 받는다.

## 7. 간단 모드

모든 화면에 1~4절 전체를 하면 작은 화면에서는 절차가 화면보다 무거워진다. 아래 조건을 **모두** 만족하면 간단 모드로 한다.

- 마커와 코드 키트(`kitPath`, 또는 `consistency.md` 7절의 기존 부품 목록)가 있는 프로젝트다.
- 만들 화면이 작업형 하위 화면이다 (설정, 목록, 상세, 폼, 관리 화면 등). 랜딩·첫 화면·대표 화면은 해당하지 않는다.

간단 모드에서 바뀌는 것:

1. **초안 요청을 한 줄로**: "이 화면에 들어갈 것과 가장 중요한 것을 적어 달라"만 묻는다. 레퍼런스는 묻지 않는다 (사용자가 주면 읽는다).
2. **구조안과 차이 공개를 한 메시지에**: 4-2(사용자가 먼저 지적)를 생략하고, 구조안 아래에 바꿈·뺌·채움을 바로 모두 공개한다. 차이가 없으면 "초안과 같음"이라고만 쓴다.
3. **판정은 차이가 있을 때만** 받는다. 차이가 없으면 바로 진행한다.

바뀌지 않는 것: 초안을 받기 전에 제안하지 않는다. 초안을 그대로 기록한다. 판정 전에 만들지 않는다. AI가 먼저 간단 모드를 건너뛰기로 바꾸자고 권하지 않는다.

완료 보고 초안 줄에 "(간단 모드)"를 붙인다.

## 완료 보고에 적는 것

한 줄로 적는다. 찾은 쪽을 나눠 적어서 사용자가 자기 지적이 얼마나 맞았는지 볼 수 있게 한다.

- 예: "초안: 차이 5건(사용자 지적 3 · AI 공개 2) → 초안대로 3 · AI안 1 · 절충 1"
- 차이가 없었으면 "초안: 차이 없음", 건너뛰었으면 "초안 없음(사용자가 건너뜀)"
